## 分析边界

本分析只读取封存的逐候选预测、学习记录、分支标签和分支内通信审计。环境调用、模型初始化、checkpoint加载、模型前向和训练更新均为0；未读取封存任务对照集。

学习方法指B的三种子集成。透明方法使用封存的 `baseline_transparent`。两者在24个预测窗口中有10个选择不同动作。本报告没有修改冻结指标、门槛或任务阶段状态。

## 重点窗口

- `train-0005/r2`：两条首命令均accepted。B的动作14虽然公开距离更长，却比动作2多得到约`0.129969`完成项，并少耗约0.534能量，最终多完成一个任务。这可能是首动作改变Hungarian后续次序的真实作用，也可能依赖该repeat后续实现；单一窗口不能区分。
- `train-0007/r0`与`r1`：B均选动作14并被accepted；透明方法的首命令均为`resource_unavailable`。收益差几乎全部来自多一个按时完成结果。
- `train-0007/r2`：B仍选动作14，但首命令为`command_lost`；透明动作8被accepted。B少约`0.128118`完成项。该repeat的公开几何、deadline和age与前两个repeat相近，但不是完全相同输入：决策时刻早1步、能量不同，完整输入哈希也不同。
- `train-0006/r2`：双方均accepted且全部任务最终完成。B的损失主要来自能耗项`-0.008575`，说明短首段公开距离没有转化为较低的整段Hungarian续行能耗。

所有10个单元的共同通信原语配对均无结果、参数或重数不一致。这排除了“共同外生调用没有配对”的解释，但不排除动作特有的命令投递结果和后续执行路径差异。

## 重复性与相反方向

没有两个repeat具有相同的完整冻结公开输入哈希。

`train-0007/r0`和`r1`中动作14的简化公开特征签名完全相同，收益方向也相同；这是一致正例。`r2`的动作14几何和deadline相同但时刻、能量及完整输入不同，并出现命令丢失和相反收益方向，因此不是“同样公开特征的严格反例”。

`train-0005`的正负repeat使用不同动作、时刻和公开特征；`train-0006`前两个repeat两种方法选择相同动作，只有r2发生分歧。这些记录不能证明同一公开状态存在稳定的相反标签。

因此，对“模型利用了可重复公开信息”与“少数外生实现或后续执行差异造成平均优势”的总体二选一结论是：**无法判断**。现有证据更直接地证明了优势集中于少数完成/投递结果，但仍有 `train-0005/r2` 这种双方均接受、后续结果显著分化的窗口，不能把全部差异归为通信运气。
