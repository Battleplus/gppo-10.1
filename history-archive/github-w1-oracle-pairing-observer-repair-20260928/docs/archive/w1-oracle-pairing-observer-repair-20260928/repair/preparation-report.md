# Oracle观察器修复准备报告

## 状态

`RUNNER_READY_NOT_APPROVED`

已建立独立修复包。旧runner-ready包、已封存attempt及其90环境步记录均未修改。

## 修复内容

- 新增`communication_observer.py`，透明代理四类冻结通信原语。
- 每次调用保存分支、调用序号、调用位置、method、完整identity、全部参数及返回值；异常先记录再原样抛出。
- 分支证据从快照后的marker开始，前缀调用不会复制进每个分支的比较切片。
- 共同调用按`method + 完整identity + 完整参数`匹配，重复调用保留次数和顺序。
- action-specific调用单列；最终送达、过期、命令接受和lease执行仍在原高层日志中，不作为随机fate比较。
- 真正的共同原语返回值不一致会触发技术停止。缺字段、空共同集合和空action-specific集合不能通过。

共享环境、通信原语、随机身份算法、W1-light profile、规则、场景、奖励、mask和标签实现未修改。修复环境源码哈希保持与完整公平重跑一致。

## 单单元入口

唯一入口仍为`launch_once.py`，但attempt和目标路径已独立。runner只执行`validation-0000/repeat-0`；它按冻结规则重新确定窗口和候选，不复用或硬编码旧7个动作。技术门完成后写入结算并退出，不调用oracle分析，不进入其余23个单元。

原始授权token未写入包，只冻结SHA-256。`RESOURCE_REQUEST.json`保持`NOT_APPROVED`。

## 预算

动态调用上限：450环境步、1次reset、18次候选扫描、426次公开规则决策、1次快照、25次分支复制、25个分支及25次强制首动作。模型、checkpoint、前向和训练全部为0。

总wall 660秒、完整CPU 1320秒、RSS 4 GiB、活动制品512 MiB、原生加导出1 GiB。分阶段额度独立，历史消耗不抵扣。

## 零调用验证

在WSL原生ext4目录、冻结Python 3.11.16和冻结运行依赖上，34项测试全部通过。测试覆盖真实W1-light通信接口的直调/观察器等价性、完整identity和参数、重复调用、故意fate不一致、参数冲突、缺字段、空共同集合、135项封存telemetry误报分类、单单元停止、标签失败、账本异常、前后身份哈希及受控导出路径。

测试未实例化真实环境；环境reset/step、模型调用和训练均为0。Windows上的目录fsync限制只作为诊断记录，最终基础设施证据来自原生ext4。

## 解释边界

本包只准备观察器动态接线门。即使未来技术门通过，也不产生oracle收益或材料性结论，不自动授权剩余矩阵，也不允许把同一技术门数据在后续报告中重复计算为两个样本。
