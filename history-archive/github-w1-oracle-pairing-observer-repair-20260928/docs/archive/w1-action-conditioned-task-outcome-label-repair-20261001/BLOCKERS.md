# Blockers

The sealed export cannot provide valid action-conditioned physical completion,
host confirmation, or expiry labels.

- `production_data.py` constructs the transition target with
  `physical_completion=None` and `host_confirmation=None`.
- The collector executes one candidate branch step and writes the window;
  it does not run the fixed continuation to termination or the 18-second
  horizon.
- All 56 saved windows have `terminated=false` and `truncated=false` for
  every saved candidate branch.
- Completion records and completion communication messages are absent.
- Saved task states are only `assigned`, `pending`, or `unreleased`; no saved
  task is explicitly `completed` or `expired`.
- The frozen default environment mode is `continuous_service_until_deadline`.
  Its physical completion lives in `TaskLifecycle.completed_at`, which the
  one-step collector did not export. Completion notices and host confirmation
  records are generated by a different `arrival_to_region` mode, so extending
  the branch alone cannot establish host-label availability under the frozen
  original environment.

Consequently, no offline repair can turn these records into valid completion,
confirmation, or expiry labels. A static/fixture proof of a host-confirmation
source in the unchanged mode is also missing; without one, that head stays
structurally unavailable. Training on fabricated labels is prohibited.
The package remains a preparation artifact with `RESOURCE_REQUEST.json` set to
`NOT_APPROVED`.
