# Limited Label Availability Confirmation (Not Approved)

The current export cannot answer whether the missing task labels are learnable.
The next independent confirmation should therefore collect labels only; it
must not train a model, select hyperparameters, or run GPPO.

The currently available sealed source identities do not establish an unused
independent confirmation set. Before any dynamic request, identify new parent
scenarios by a frozen canonical generator order and verify they were not used
by historical training, model selection, prediction confirmation or task
material. An eight-parent, three-repeat design is a provisional envelope, not
an approved matrix. Preserve no-opportunity units and do not replace them.

At each decision point, freeze the public input and all legal candidates. For
each candidate, execute the candidate once and then the fixed
`hungarian-v1` continuation until native termination or the existing 18-second
horizon. Persist every continuation step, command identity, communication
record, `TaskLifecycle.completed_at` with command/UAV/task identity, host
confirmation evidence if the unchanged native mode can produce it, expiry
state, and the continuation identity. The fixed continuation is part of the
label, not a learned policy. First verify with static source inspection and a
bottom-boundary fixture that the frozen default mode can emit each target;
do not switch to `arrival_to_region` merely to create host labels.

The confirmation gate is data-contract only:

1. All eight parents have at least one complete valid window, or the run stops.
2. Every non-NOOP candidate has an auditable action and continuation identity.
3. Physical completion and host confirmation each have nonzero valid coverage
   under the unchanged environment mode; otherwise stop and report the head
   as structurally unavailable. Their valid counts and unknown reasons are
   reported separately.
4. At least two candidates in a window have differing observed task outcomes
   for at least one task-related head, without using utility to choose windows.

Failure of this gate stops the label line. It does not authorize model
training, a new predictor, a GPPO run, or a changed prediction gate.

The provisional collection envelope is 24 decision windows and at most 600
candidate branches, with at most 18 native steps per continuation plus the
decision prefix. This is a sizing placeholder only. Exact parent identities,
environment-step accounting, wall, CPU, and storage amounts must be derived
and frozen before any dynamic authorization; no budget is approved here.
