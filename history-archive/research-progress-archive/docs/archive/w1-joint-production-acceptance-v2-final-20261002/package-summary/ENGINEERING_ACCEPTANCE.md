# 联合包最后工程验收 v2

本版沿用v1的24/8/8父场景、固定种子、G1/G2模型和目标、数据门、
预测指标与研究预算。GPPO训练和任务对照仍不在本申请中。旧包、
已停止attempt、原始制品和科学结论保持原状。
本版正式研究身份为 `w1-task-outcome-g1-g2-joint-v2-once`，仅为 proposed。
资源申请仍为 `NOT_APPROVED`，`runner_ready=false`，不能正式启动。

## CPU计量边界

1. Windows冻结控制器：身份核对、SSH、暂存上传、下载校验和本地
   收尾计入控制器范围。原30秒CPU/30秒跨系统预留保持不变。
2. 服务器外层 `metered_joint_entry.py`：等待内层完整退出。内层
   Python启动、实际collector、学习与预测、checkpoint、结算、受控
   导出、最后写入及退出CPU只按一份累计子树用量计费。内层快照
   仅用于分解，绝不能再次加到寿命总量上。
3. supervisor：使用已等待后代的内核累计ticks与活跃树；启用
   subreaper收回孤儿。树扫描不可核验、PID复用或累计量回退即停止，
   不把未知范围当0。不声称多PID扫描是原子快照。
4. worker：每次阶段切换前确认没有尚未等待的子进程，记录自身及
   已等待后代CPU，使用SO_PEERCRED认证的本地socket同步确认。
   supervisor将阶段CPU和wall核对后才放行。短阶段不能靠轮询省略。
5. GPU登记查询子进程单列CPU。启动前查询归入暂存；首次学习
   GPU绑定查询记录独立用量，按既有阶段额度保守计费。
6. 外层最后登记/写入/打印无法自我测得完整退出用量，明确预留
   3秒CPU、5秒wall，并从原有结算80秒CPU/120秒wall扣取。
   单线程外层在收尾前设置CPU硬限制和alarm；无法结束的内核
   不可中断I/O仍是完整wall封顶的限制，强杀/缺最终状态属于技术停止。
   预留不是单项操作的实测值，不能写为零开销。

旧版0.274925秒差值无法从未保存的时间边界追溯归因，勘误保留。
新版用同期快照、各阶段行和外层waited寿命解释差值，不提高0.05秒
同范围一致性容差。具体可执行约束见 `cpu-accounting-contract.json`。

`cpu_scope_complete=false` 和 `cpu_scope_hard_enforcement=false` 是
supervisor 的既有保守状态：没有 delegated cgroup，运行中 CPU/RSS
超额检查仍是采样式，不能保证在瞬时跨越上限之前阻止计算。
外层等待退出后的累计结算与运行中硬封顶是两个不同保证。
异常情况下缺少内层结算、无法回收后代或最后写入未完成，必须保留
`accounting_complete=false`，不得将缺失部分填0或报告完整验收。
Windows收尾计入既有30秒CPU预留，但不具备该预留的操作系统硬限制。
外层先持久化finalization_pending结算主体，再追加终态登记并持久化
最终回执。登记文件与结算文件不是原子事务；后续写入失败时真实登记
可能已SUCCEEDED，但流程仍属technical_stop，不能伪称两个制品均闭合。

## 本地实际执行证据

本地 Ubuntu-24.04 冻结CPU解释器首次完整回归141项，退出0；
后续worker入口与结算修复分别补跑受影响模块，全部证据保存在包外。
主生产流水线仅替换底层环境：2训练/2选择/8确认父场景、1 epoch，
12模型初始化或加载、84前向、12反向/更新、6 checkpoint写/读、420样本评价。
另一次直接production_world序列回归：12初始化或加载、66前向、
6反向/更新、6 checkpoint写/读、330样本评价。
这些是实际合成模型计算，不是零调用，也不是正式24/8/8矩阵结论。
额外真实短子进程测试在最后快照后消耗0.08秒CPU，最终waited
用量恢复至少0.07秒尾段，并证明嵌套快照不会再次加入累计寿命。
阶段集成测试真实运行supervisor、worker、socket与三个短CPU子进程。
源文件与正式科研配置对照见包外 `research-invariants.json`。

## 服务器验收与授权边界

独立工程验收请求使用冻结服务器隔离解释器和独立工程路径，
复用Windows SSH运输及登记机制。只用合成父场景和底层环境替身，
实际执行production collector、训练/选择、checkpoint恢复、逐候选
预测、指标复算、账本、结算和导出；不读取封存研究确认集。
每项合成模型/优化/checkpoint调用记录真实非零计数。
正式24/8/8矩阵和真实模拟器并未由合成验收验证。

远端计算、安装依赖或创建工程执行目录均需要新的有限授权。
本轮不进行这些操作。不得修改共享Python/CUDA，GPU1无独占资源
或运行时身份不符即停止，不切换GPU，不干扰HARL。登记需要用户
真实姓名，不以共享账号替代。没有登记回读和PID/GPU核验不计算。

## 上线判定

只有独立Luna源码复核、最终字节正式入口预检、本地进程计量回归
以及实际服务器工程验收均有相应证据，才能将runner_ready设为true。
不能把预检称作训练链验收，也不能把预设门控夹具称作模型效果。

另一个具体阻断是远端只读预检与SSH/SFTP帮助进程CPU仍只有30秒
收费预留，既未逐项实测，也未核验该预留为硬上界。工程入口保留远端
阶段和导出证据，但在这一范围未核验时禁止overall complete，标记
cpu_scope_unverified。它是工程计量阻断，不是标签或模型效果失败。
本地最终证据和身份放在包外；最终冻结后不再改写包内内容。
