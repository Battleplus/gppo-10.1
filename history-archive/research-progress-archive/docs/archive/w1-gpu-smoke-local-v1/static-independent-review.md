## Reuse Conditions

`_run_bounded_tests` itself does not call `validate_request`, perform remote registration, or replace production training functions. It imports the four tests, sets `W1_SYNTHETIC_TEST_DEVICE=cuda:0`, installs accounting guards, runs each original test method, and verifies aggregate counters plus synthetic evidence ([acceptance_entry.py:574](E:/Z%E5%8D%9A%E5%A3%AB/diagnostic-work/w1-gpu-smoke-consolidated-acceptance-v3/package/acceptance_entry.py#L574)). The local entry can therefore construct local request/meter objects and invoke this function directly without entering `_run_server_acceptance`.

Do not run only the joint test through this wrapper: `CallBudgetMeter.verify()` requires the aggregate totals from both the joint and sequence-world tests: 24 initializations/loads, 150 forwards, 18 backwards, 18 optimizer updates, 12 checkpoint writes, 12 loads, and 750 sample evaluations. CUDA context initialization must total exactly one ([acceptance_entry.py:39](E:/Z%E5%8D%9A%E5%A3%AB/diagnostic-work/w1-gpu-smoke-consolidated-acceptance-v3/package/acceptance_entry.py#L39), [acceptance_entry.py:395](E:/Z%E5%8D%9A%E5%A3%AB/diagnostic-work/w1-gpu-smoke-consolidated-acceptance-v3/package/acceptance_entry.py#L395)). `charge()` records before the operation and does not roll a charge back if that operation raises.

Before invoking the wrapper, the local process needs to map the actual physical GPU to logical `cuda:0`, initialize one CUDA context, bind the imported `torch` object to `GpuResourceMeter`, and record that context once. The wrapper's first GPU process snapshot occurs at the start of its first phase and requires the current PID to already appear as the sole compute PID; subsequent snapshots also enforce the memory ceiling ([acceptance_entry.py:435](E:/Z%E5%8D%9A%E5%A3%AB/diagnostic-work/w1-gpu-smoke-consolidated-acceptance-v3/package/acceptance_entry.py#L435), [acceptance_entry.py:457](E:/Z%E5%8D%9A%E5%A3%AB/diagnostic-work/w1-gpu-smoke-consolidated-acceptance-v3/package/acceptance_entry.py#L457), [acceptance_entry.py:642](E:/Z%E5%8D%9A%E5%A3%AB/diagnostic-work/w1-gpu-smoke-consolidated-acceptance-v3/package/acceptance_entry.py#L642)).

## Budget Traps

- `ResourceMeter.check()` uses `server_wall_seconds` and `server_complete_process_cpu_seconds`, subtracting the terminalization reserve. The current server request uses 150/300 there even though the outer 180/360 limits are preserved separately. A local standalone cap of 180/360 needs the local meter's server fields set to 180/360; otherwise the effective run cap stays 150/300. The closing check adds the 5-second and 3-second reserves back to the observed totals ([acceptance_entry.py:118](E:/Z%E5%8D%9A%E5%A3%AB/diagnostic-work/w1-gpu-smoke-consolidated-acceptance-v3/package/acceptance_entry.py#L118), [acceptance_entry.py:262](E:/Z%E5%8D%9A%E5%A3%AB/diagnostic-work/w1-gpu-smoke-consolidated-acceptance-v3/package/acceptance_entry.py#L262), [acceptance_entry.py:331](E:/Z%E5%8D%9A%E5%A3%AB/diagnostic-work/w1-gpu-smoke-consolidated-acceptance-v3/package/acceptance_entry.py#L331)).
- `ResourceMeter.sample()` reports absolute process-plus-reaped-child CPU since process start, not a delta from meter construction. Run the local entry in a fresh Python process and start wall timing before setup if setup is intended to count toward 180 seconds. CPU from a live child is not in `RUSAGE_CHILDREN` until that child is waited/reaped; the supervisor test waits for its subprocesses, but the meter alone is not a live process-tree sampler. RSS is root-process-only, explicitly excludes descendants ([acceptance_entry.py:226](E:/Z%E5%8D%9A%E5%A3%AB/diagnostic-work/w1-gpu-smoke-consolidated-acceptance-v3/package/acceptance_entry.py#L226), [acceptance_entry.py:296](E:/Z%E5%8D%9A%E5%A3%AB/diagnostic-work/w1-gpu-smoke-consolidated-acceptance-v3/package/acceptance_entry.py#L296)).
- `GpuResourceMeter.check_framework_memory()` checks both PyTorch peak allocated and peak reserved against the same ceiling; the `nvidia-smi` process snapshot separately checks aggregate process memory. A 4 GiB cap therefore constrains allocator reservation too, not just live tensor bytes. The sampling code does not reset PyTorch's high-water mark ([acceptance_entry.py:438](E:/Z%E5%8D%9A%E5%A3%AB/diagnostic-work/w1-gpu-smoke-consolidated-acceptance-v3/package/acceptance_entry.py#L438), [acceptance_entry.py:472](E:/Z%E5%8D%9A%E5%A3%AB/diagnostic-work/w1-gpu-smoke-consolidated-acceptance-v3/package/acceptance_entry.py#L472)).
- Storage/RSS are sampled counters too. `ResourceMeter` samples tree bytes at most every 0.5 seconds unless forced, and charges the package root only if the caller explicitly calls `charge_package_root`; local work/evidence roots need to be passed to `bind_paths` ([acceptance_entry.py:249](E:/Z%E5%8D%9A%E5%A3%AB/diagnostic-work/w1-gpu-smoke-consolidated-acceptance-v3/package/acceptance_entry.py#L249), [acceptance_entry.py:278](E:/Z%E5%8D%9A%E5%A3%AB/diagnostic-work/w1-gpu-smoke-consolidated-acceptance-v3/package/acceptance_entry.py#L278)).
