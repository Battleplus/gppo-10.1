# 训练准备边界

当前可以证明：独立 Python/PyTorch/CUDA 候选运行时通过两卡微型合成检查，并可进行显式只读身份预检。

当前不能证明：生产标签资格覆盖、正式世界模型训练数据有效性、GPPO 在 GPU 上的生产闭包、生产矩阵显存峰值、独占资源分配、研究门通过或任务收益。

标签准备和模型训练分别申请。v6 只申请八个冻结父场景的有限标签资格采集，不申请任何模型初始化、前向、checkpoint 或训练额度。其 NOT_APPROVED 状态不表示已有动态授权。

标签采集成功后，下一训练包至少应明确：

1. 固定训练、模型选择、预测确认和封存任务父场景身份，开发标签不得假称新的独立确认集。
2. G1/G2 的任务后果目标、有效掩码、公开历史、候选身份与固定续行，unknown 不填零。
3. GPPO 多目标、偏好相似度与 PreCo 更新，以及行为/回放先验和 mask 一致性。
4. G1 相对透明方法和 G2 相对 G1 的预注册推进分支；原任务效用增量和成本标准不降低。
5. GPU 型号/UUID、单卡或双卡使用规则、显存上限、完整进程 CPU、wall、存储及逐调用上限。
6. 完成生产 GPU 零步身份预检和底层替身端到端测试后，生成唯一入口、新 attempt、新冻结摘要和 NOT_APPROVED 申请。

本轮未生成一份可以绕过标签资格采集的训练授权或训练入口。
