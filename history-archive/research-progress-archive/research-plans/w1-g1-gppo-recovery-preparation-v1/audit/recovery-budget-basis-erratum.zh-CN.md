# 预算依据勘误

本勘误优先于此前独立审查与 `recovery-audit` 中将 3060 wall / 2160 CPU 秒直接并列为申请估算的表述。

`RESOURCE_REQUEST.json` 的 `budget_basis` 对两条待补训路由给出的精确 wall 外推为：

`0.49142533680424094 秒/step × 4096 steps = 2012.8781796 秒；× 1.5 安全系数 = 3019.3172693 秒。`

本次申请的训练 wall cap 是 3200 秒，因此相对该精确外推的 wall 余量为 180.6827307 秒。此前审计的 3060 秒是把同一外推向上取整到整分钟的独立保守估算，不是申请 `budget_basis` 中的实际精确外推；它相对 cap 的 140 秒只是按该粗取整得到的余量。

训练 CPU cap 是 2600 秒。申请说明 CPU cap 按 stage CPU/wall 比估算，但没有给出精确 CPU 点估计。此前的 2160 秒是独立审计用旧 incomplete stage 比率计算并向上取整到整分钟的粗估，不是申请实际 `budget_basis`；2600−2160=440 秒不能表述为当前申请依据下的正式 CPU 余量。

任务确认预算仍为 1200 wall / 1600 CPU 秒，240 episodes。136.708 秒策略决策组件 proxy 仍只是下界，不能证明任务 cap 充足。全局 cap 仍为 4670 wall / 4390 CPU 秒。本勘误仅更正估算来源和口径；未运行全审计，未修改 package。
