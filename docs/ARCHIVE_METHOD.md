# 档案范围与校验方法

本档案整理用户历史进度说明，并以本地原始报告、冻结实现及机器结果交叉核对。最新状态已更新至 2026-10-05 的恢复实验正式结果，未停留在早先“恢复准备完成”的会话摘要。

## 文件类别

- `README.md`、`docs/`：本次编写的中文研究交接说明。
- `evidence/`：选定小型原始报告、协议、复核、指标及源码的原字节副本；不执行其中的命令。
- `provenance/source-inventory.json`：每个原字节副本的来源、归档位置、大小、SHA-256；注明复制后逐项一致。
- `provenance/artifact-locations.json`：关键大制品的本地位置、大小及 SHA-256；只读文件字节计算摘要，没有模型加载。
- `provenance/archive-hashes.json`：除自身以外的全部档案文件摘要，避免循环自哈希。
- `tools/verify_archive.py`：仅使用 Python 标准库，校验档案内容、来源索引副本及本次撰写文档的相对链接；不运行环境、模型或训练。

在仓库根目录执行 `python -B tools/verify_archive.py` 即可离线核验。本仓库没有可用训练授权，也不提供已消费 attempt 的重启入口。

## 公开归档边界

目标仓库为公开仓库。仅发布研究文档和明确选择的小型材料；不复制 token、外部授权、私钥、密码、SQLite、checkpoint、完整原始 JSONL、大型日志或整份工作区。文档中描述授权制度或保存摘要不等于包含可用凭据。

原始证据中的本机路径用于溯源，不能在 GitHub 网页直接访问。`evidence/` 内相对链接和旧绝对路径保留原字节，可能指向未上传材料；本次新写的导航使用仓库内可用链接。

这是选择性证据归档，不是完整实验可复现包。大制品留在本地，摘要用于后续查验；仅有摘要不能替代数据本身。没有证明归档外所有历史文件都已备份，也没有改动原来的 Git 暂存区或锁。

历史报告的远端状态是写作当时的状态；本仓库是否已发布以 GitHub 实际 commit 和远端文件校验为准。此次发布不会追溯改写那些历史报告。

## 本次发布方式

Git HTTPS 克隆遭遇连接重置，改用已认证的 GitHub API 发布。空仓库先经 REST Contents 接口创建 README，初始化提交 `91751a8bcaa94e3b2078a17b2055c434e68996fe` 被 GitHub 标记为 `unsigned`；不能声称这一步有签名，也没有删除该历史。后续完整档案使用支持 GitHub 自动签名的 GraphQL `createCommitOnBranch`，以 expectedHeadOid 防止覆盖并发更新，并在发布后核验签名及整个远端文件树。

这没有关闭本机 Git 签名配置或操作 SSH 私钥。历史项目签名代理阻塞的记录仍保持原样；本次 API 发布情况与那些历史状态分别报告。
