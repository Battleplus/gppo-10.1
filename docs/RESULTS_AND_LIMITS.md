# 研究结果、限制与必要勘误

## 预测改善与任务失败可以同时成立

G1 在固定 Hungarian 续行的预测评价中，相对透明参考的 regret 从 0.234002 降至 0.050967，改善约 78.2%；这保留为特定参考、特定标签下的正结果。

透明参考在八个窗口全部选择 NOOP：乐观续行公式把候选完成收益拉平，主动动作还有能耗扣分。审计未发现评分符号、mask 或并列规则错误。它是较弱的实际比较参考，不能等同于真正 Hungarian 调度器。事后使用首步透明评分的敏感性分析也不能替代原冻结门。

任务验证让模型辅助 GPPO 逐步调度；标签却描述 Hungarian 续行。两者有续行策略和访问状态分布的差异。现有结果证明“这套迁移方案未带来任务增量”，但尚不能单独确定失效来自预测误差、先验尺度、策略训练不稳定还是续行失配。

## G2 的事件指标为什么不是成功

自动事件 Brier 从 G1 的 0.231531 降到 G2 的 0.029816，但 G2 regret 增至 0.101352。部分自动事件有效样本全为正例，瞬时物理完成和主机确认两个头全 unknown；不能以综合 Brier 声称任务完成预测改善。

另设的生命周期头有有效监督：物理完成 Brier 0.140279→0.140022，仅微小改善；过期 0.140253→0.140810、确认 0.145791→0.158712，反而变差。G2 没有通过独立排序增量门，未进入后续 GPPO 四臂。

## 稳定性和因果归因边界

- G1 离线三个种子动作完全一致仅 3/8 窗口。三个种子方向一致，不等于充分稳定。
- GPPO 相对 T 只有一个种子正向；报告全部种子，不能只保留 8301。
- 八个父场景是统计单位；同一父场景的候选、repeat 和共享 H 不应被当作更多独立场景。
- G0/T 本次轨迹相同，不是两份独立的正反证据。
- G1 即时先验仅改变 1 次采样动作，不足以把所有任务差值归为这一次动作；其训练得到的策略参数也发生了变化。
- unknown 主机确认不填失败，不把物理完成代替主机确认。
- 历史已分析数据转为开发证据；不能在同一评价集反复调参后再宣称独立确认。

## 历史来源与标签勘误

1. **56 窗口/771 候选不是 E2E 合成夹具。** v2 复用审计曾误标 `TEST_FIXTURE_ONLY`；v5 来源审计据正式生产 collector、运行身份和不同夹具摘要更正为真实 W1 模拟器生成数据，非实飞。旧错误记录保留，引用时以[来源勘误](../evidence/history/source-erratum-v5.md)为准。
2. **旧 collector 配置语义与引用的 environment.json 不一致。** 源码默认 continuous_service_until_deadline / physical_service；另一个 fair-rerun 文件是 arrival_to_region / physical_arrival。旧结果不混合，也不把后来配置追溯套入旧采集。
3. **旧一步标签不能当终局后果。** 旧 EAWM 的 regret 与 Brier 可复算，但不足以证明物理完成、过期或确认预测；旧 `prediction_gate_stop` 不改判。
4. **v6 有 9 条首命令完成归属假阳性。** 命令身份一致不足以证明已经完成；单独勘误，不改原始数据。三个主标签仍有效，但原 `true_utility` 仅首步效用，缺失续行奖励，故另采完整序列。
5. **最新恢复实验不存在“累计 wall 超本次预算”的结论。** Luna 初稿混用了历史累计和新 attempt 上限，已更正；完整资源验收 false 的原因仍是计量缺口及旧未决调用。
6. **Windows 浮点复算异常不是正式运行失败。** 22 处最大 8.3267e−17 差异导致额外字典精确比较失败；冻结 WSL Python 3.11.16 复算逐字段一致，未重跑实验。

## 能说与不能说

可以说：已完成生产模拟器数据采集、世界模型学习、GPPO 训练、四臂评价和成本测量，得到可复算的负任务结果。当前 G1 的离线排序正结果尚未转化为 GPPO 调度价值。

不能说：世界模型总体无效、JEPA 论文路线被否定、真实无人机调度已成功、G2 事件监督改善终局任务、当前方案胜过 Hungarian、完整跨系统资源验收已通过，或继续增加训练量必然得到正收益。
