# 腾讯会议后续实验计划

日期：2026-09-29。状态：规划稿，未授权任何动态调用；不是新的冻结协议。

## 结论与研究问题

下一项工作建议落实会议的“动作后果作为强化学习决策先验”，先做冻结策略的一次干预对照。当前中心化辅助损失路线封存，不扩训、不调系数、不重新解释原 prediction_gate_stop。

核心问题：在原修复后 W1-light 任务、相同公开信息与合法动作边界下，动作相关预测能否改善同一个冻结 GPPO 基础策略的决策，并达到相对强规则的实用增量？这是拟检验假设，不是已有结论。

当前结果仅支持提出这些假设。当前8个确认父场景和已诊断窗口均转为开发证据，不再作为新确认集。

## Block 1：一次干预的对齐合同（必须，先零调用完成）

- 基础策略：选择一个修复后已有的 GPPO_noWM checkpoint，冻结文件、架构、公开输入处理、动作mask、推理模式、偏好权重和种子。不在新评价结果上挑选checkpoint。
- 先核对该策略是否曾见过拟用场景。新预测确认和任务父场景应与该策略训练、预测器训练及所有已分析场景按父场景身份隔离，不能只修改名称。若现有tape不足，预先从同一个原任务生成器取新种子；这需要计入新申请。
- 基础checkpoint的历史表现较弱，这是风险，不隐瞒。即使相对它有增量，也必须与Hungarian比较才能宣称实用优势。
- 固定前缀由该基础策略执行；每个episode只在首个预先定义的公开合格窗口干预一次，之后恢复同一基础策略。窗口条件从现有公开条件继承，不按故障或收益筛选。
- 预测目标：候选首动作后，在该冻结基础策略续行下的剩余原始折扣效用。标签必须注明新的continuation_id。
- 旧Hungarian续行的398条标签只作开发/管道参考，不充当新GPPO续行价值的训练真值。
- 可读记录：task/UAV身份、观测与接收时间、字段age、pending命令、已确认continuation，以及其决策前公开来源。输入冻结在任何分支之前，未来记录只用于标签。
- 不在这个实验中改变通信概率、故障强度、任务难度、合法mask、时限、奖励或偏好权重。

停止条件：无法证明续行匹配、训练/评价隔离、公开信息边界，或预算无法覆盖闭环时，停在准备阶段，不先消耗动态预算。

## Block 2：匹配续行的监督学习（必须，需新授权）

- 方法只保留一个：轻量动作后果预测器，先沿用原A的绝对收益目标和小网络，不继续搜索中心化系数，不同时增加概率头、分布头和新架构。
- 数据覆盖全部合法候选，包括合法NOOP；真实拒绝、丢失、超时及损坏结果全部保留。unknown使用显式有效性掩码，不填零。
- 训练父场景、选择父场景、预测确认父场景、最终任务父场景四组隔离。三训练种子固定，不能按确认结果选最好种子。集成继续作为预注册部署规则；单种子仅作诊断。
- 每个父场景采用预定外生重复，候选之间保持已有共同通信原语随机配对。不同repeat的前缀与公开状态可以不同，不能宣称它们是“同一公开状态下的多次未来”。
- 标量回归的结果称为样本分布上的动作后果估计；SmoothL1不自动保证得到条件期望。不要将一次分支实现称作动作期望价值真值。
- 不要求本轮识别全部通信因果机制。若另需固定决策前状态下的未来重采样，必须单列未来随机机制协议，不能在当前合同中随意更换exogenous_key。
- 模型选择只在选择集进行，A/B损失实验已结束；新的选择指标建议以父场景宏平均regret为主、MAE为辅，须在独立评价前冻结。不能在看到确认集后变更。
- 保存全部逐候选三种子预测、集成结果、标签、接受/投递状态、输入身份及不确定字段。

预测推进条件：在新确认集上，学习评分相对透明评分的父场景宏平均regret严格更低，并报告父场景方向与区间；不再沿用“B比A改善0.005”这个旧辅助目标专用条件。新门槛是新实验合同，绝不能追溯使旧实验通过。样本量不足则结论限制为开发结果。

## Block 3：真正的先验接入（必须，与Block 2一起申请条件执行）

四臂固定：

1. 同一冻结 GPPO_noWM 基础策略。
2. 同一策略 + 透明历史后果评分先验。
3. 同一策略 + 学习动作后果评分先验。
4. Hungarian强规则。

三条GPPO臂使用同一checkpoint和原生推理模式。若是随机策略，固定配对策略随机键，不能未经说明改成贪心策略。策略只在合格窗口被干预一次，后续恢复原策略，因此与监督标签的续行匹配。

评分形式：final_logit[a] = base_logit[a] + lambda * score[a]。非法动作仍为负无穷，lambda=0严格还原基础策略。透明和学习先验采用同一预先定义的单位/尺度处理；只减窗口常数不会改变排序。系数的固定值或有限选择程序只能在训练/选择集决定，评价前冻结。

不直接采用旧代码中的score数值范围假定：透明评分绝对偏移较大，需检查尺度公平性。若使用标准化，参数只能由训练/选择集确定，不使用评价标签。

不得把Hungarian续行价值直接注入GPPO，再声称这是对GPPO动作真实价值的预测。不得在这个首轮实验同时修改奖励并重训策略。

任务指标与成功解释：

- 主要：原始效用的父场景配对差值；学习先验必须优于无先验和透明先验，不能只与弱学习策略比较。
- 实用性：学习先验相对Hungarian宏平均增量达到既有0.01标准，且完整CPU均值≤10ms、wall p95≤50ms。若只改善GPPO但仍明显落后Hungarian，结论是“融合有增量但实用性不足”。
- 至少半数任务父场景取得正向增量的要求作为建议门，具体比较对象、区间判读和样本量必须在冻结协议中明确。不把重复或候选行当独立父场景。
- 次要：物理按时完成、主机按时确认、能耗、丢包/拒绝事件、NOOP、先验改变动作比例。主机unknown不归为成功或失败。
- 每臂分别记录特征构造、前向、融合、动作选择成本，不能混合A/B或不同策略。
- 所有父场景计入报告；无合格窗口保留。相同动作、零收益、负收益完整保留。

结果只能支持一次干预、特定W1-light分布及冻结策略；不能直接声称每步使用先验、联合训练GPPO或世界模型一般有效。

## Compute and data budget

当前没有足够证据给出可信的新步数、训练更新或wall上限。上一轮实耗348.75秒wall、732.93秒CPU可作为参考，但不能直接外推为新闭环保证。不得沿用旧未用余额。

准备阶段须提供以下可复算公式：

- 标签环境步 ≤ N_label_parent × R_label × (P_max + C_max × L_max)。
- 任务环境步 ≤ N_task_parent × R_task × 4 × H，H沿用原合同。
- 推理前向按完整窗口批次计数，三模型集成每臂每干预窗口三次；checkpoint及模型构造计费语义须明确。
- 训练更新从完整训练窗口数、每更新窗口数、epoch上限、三个种子推导；选择前向单独包含。
- 全局和阶段上限、native与导出存储、完整CPU/RSS及结算预留分别计算。

样本量以父场景为独立单位。先用已分析开发数据估计效应集中与方差，给出精度/预算权衡，不用新确认数据逐步加样直到显著。新确认父场景数量不应因习惯自动沿用8；无法达到精度要求则降低结论强度，而不是降低收益门。

## Risks and stop/go rules

- 旧基础GPPO弱：始终保留Hungarian，不把相对增量等同于实用性。
- 可学习信号集中：报告所有父场景及极端窗口贡献，不只展示获胜案例。
- 单次随机后果被误当期望：保留通信与接受标签、配对重复，严格限制期望价值措辞。
- 标签续行错配：这是新准备包的首要合同检查；不混用旧Hungarian标签。
- 先验不改变动作：只能报告该融合机制无决策作用，不靠增大系数事后补救。
- 成本失败：即使效用提高也不通过实用性验收。
- 数据清洗偏差：剔除日志损坏，不剔除真实坏结果。
- 新技术停止：封存，不自动修复重跑；只读预检、依赖导入、生产worker路径与底层接口回归在正式授权前完成。

## 暂不开展

不同时做奖励塑形、每步滚动规划、RL联合重训、新网络搜索、通信难度加大或专挑规则失败场景。评分先验验证通过后，再另立协议检验奖励塑形或闭环联合训练。
